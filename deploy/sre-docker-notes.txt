虾球 Hub — SRE 平台 Docker 表单（双包 + 仅 Node，无 Nginx）
================================================================
预发连不上库：先看 deploy/预发数据库连接配置说明.txt（DATABASE_URL 配在「运行环境变量」，不是 .env.pre）

WORKDIR
  /opt/web

COPY
  建议：仓库根目录全部文件 → /opt/web（勿漏 prisma/、package-lock.json、scripts/、web-start.sh）

RUN（与 package.json 中脚本一致，无 widget）
  1) . /root/.nvm/nvm.sh && nvm use 20 && cd /opt/web && npm ci
  2) cp -R ./ /opt/pre && cd /opt/pre && npm run build:pre
  3) cp -R ./ /opt/prod && cd /opt/prod && npm run build:prod

CMD
  ["sh", "web-start.sh"]
  （工作目录需为 /opt/web；脚本内 cd /opt/$CONF_ENV 后执行 npm run start，要求该目录下为完整构建树含 node_modules）

运行期环境变量（同一镜像，两套部署各配各的）
  CONF_ENV=pre   → 使用 /opt/pre 下构建产物
  CONF_ENV=prod  → 使用 /opt/prod（默认）

  数据库、Redis、MinIO、Hub 密钥等「连哪里」不在仓库里分 pre/prod 两个文件写死，
  而在「预发工作负载」和「生产工作负载」上分别配置（同一镜像，环境变量不同）：
  - SRE / K8s：预发 Deployment 一套 ENV/Secret，生产 Deployment 另一套 ENV/Secret。
  - 变量名与含义见根目录 .env.example（如 DATABASE_URL、REDIS_*、MINIO_*、HUB_*）。
  预发 Pod 填预发库的 URL，生产 Pod 填生产库的 URL；与 CONF_ENV 只是「选 /opt/pre 或 /opt/prod 目录」组合使用。

预发/生产构建差异（只影响打进前端的 NEXT_PUBLIC_*）
  构建前准备 .env.pre / .env.prod（模板见 .env.pre.example、.env.prod.example），
  或仅在构建命令前 export NEXT_PUBLIC_SITE_URL=...
  说明：.env.pre / .env.prod 默认只给 build:pre / build:prod 用；连库配置除非你们平台在「启动容器」时再挂载 env 文件，否则仍按上面「两套部署各注入」处理。

迁移
  勿写进镜像构建 RUN；在发布流水线对目标库执行 npx prisma migrate deploy
