# 项目结构（NON-NEGOTIABLE）

## 目录结构

```text
src/
├── app/           # Next App Router 页面、布局、路由处理器
├── components/    # 通用组件与业务组件（按领域分组）
├── generated/     # 代码生成产物（如 Prisma Client）
├── lib/           # 工具函数、业务服务与跨层公共逻辑
├── middleware/    # 中间件拆分模块
├── tests/         # 测试代码
├── themes/        # 主题与字号等 UI 系统能力
└── middleware.ts  # 全局中间件入口
```

## 结构约束

| 类型 | 目录 | 规范 |
|------|------|------|
| 页面路由 | `src/app/` | 页面以 `page.tsx` 为入口；布局使用 `layout.tsx`；动态段使用 `[param]` 目录 |
| API 路由 | `src/app/api/` | 统一使用 `route.ts` 导出 HTTP 方法处理函数（`GET`/`POST` 等） |
| 通用 UI 组件 | `src/components/ui/` | 放置跨业务可复用组件，避免携带业务数据依赖 |
| 业务组件 | `src/components/*` | 按业务域分目录（如 `skills`、`rules`、`admin`），避免单层过度堆积 |
| 公共能力 | `src/lib/` | 纯函数、数据处理、服务封装优先放在此目录，减少页面层重复实现 |
| 主题系统 | `src/themes/` | 主题定义、切换逻辑、Provider 集中管理，不分散到页面组件 |
| 生成代码 | `src/generated/` | 仅由生成工具更新，业务代码禁止直接手改 |
| 测试代码 | `src/tests/` | 约定放置集成/接口测试；组件单测可与组件同目录放置 `*.test.tsx` |

## 路由目录内的组件放置规则

- 路由私有组件优先放在 `src/components/<domain>/`，避免在 `src/app/` 下创建大量匿名局部组件文件。
- `src/app/` 目录以路由与数据编排为主，UI 片段抽离到 `src/components/`。
- `loading.tsx`、`not-found.tsx`、`error.tsx` 等路由保留文件仅保留路由态语义。

## Mock 数据策略

- 当前仓库未检测到固定的 `mock/` 目录约定。
- 如需临时 Mock，优先在测试目录中通过测试桩实现，避免将临时 Mock 常驻生产目录。

> 说明：文件扩展名以仓库实际文件为准（当前以 `.ts` / `.tsx` 为主）。
