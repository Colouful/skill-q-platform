# 组件规范

## 组件结构（NON-NEGOTIABLE）

- 使用 React 函数组件 + TypeScript（`.tsx`）。
- 组件 Props 使用显式类型（`type` / `interface`）声明，避免 `any`。
- 优先使用命名导出；允许“主组件 + 辅助常量/variants”同文件导出。
- 展示组件与数据逻辑解耦：页面层负责数据编排，组件层负责渲染与交互。
- 使用 hooks、浏览器 API、事件处理时必须显式添加 `"use client"`。

## 组件目录结构

当前项目采用“按业务域分组 + UI 原语层”结构：

```text
src/components/
├── ui/                  # 通用基础组件
├── admin/               # 管理端组件
├── skills/              # Skill 业务组件
├── rules/               # Rule 业务组件
├── layout/              # 站点布局组件
├── search/              # 搜索相关组件
└── ...                  # 其他业务域组件
```

## 组件层级规划

- 全局通用：`src/components/ui/`
- 领域复用：`src/components/<domain>/`
- 页面私有：优先先尝试沉淀到 `<domain>` 目录；仅极少量一次性片段可留在页面文件

组件放置决策：
1. 跨页面可复用 -> `ui/` 或 `components/<domain>/`
2. 仅某领域使用 -> `components/<domain>/`
3. 强路由耦合且一次性 -> 可保留在 `src/app/**/page.tsx` 内部

## 组件编写要点

- 样式优先使用 Tailwind 原子类 + CSS 变量（如 `var(--pixel-*)`）。
- 组件间通信优先 Props，跨层共享再使用 Context Provider。
- 保持组件“单一职责”：复杂流程拆分为容器组件 + 展示组件。
- 通用交互（按钮、输入、对话框）优先复用 `src/components/ui/` 现有实现。
