# 状态管理规范（NON-NEGOTIABLE）

## 基础规范

- 当前项目未引入 Redux / Zustand / Pinia 等独立全局状态库。
- 全局共享状态采用 React Context + Provider（如主题、字号）。
- 主题相关能力可结合 `next-themes` 使用（如 Toaster 主题同步），业务全局状态仍以 Context 为主。
- 状态应按“作用域最小化”原则设计：局部状态优先组件内管理，跨层共享再上提 Provider。

## 目录结构

```text
src/themes/
├── ThemeProvider.tsx
├── FontScaleProvider.tsx
├── useTheme.ts
└── useFontScale.ts
```

## Store 编写规范

- 使用 `createContext + useContext + useState/useReducer` 组合实现状态容器。
- Provider 负责状态初始化、持久化同步与副作用管理。
- 对外暴露稳定 Hook（如 `useTheme()`），避免业务层直接操作底层 Context。
- 禁止在多个组件中复制同一份全局状态逻辑。

## 在组件中使用

- 业务组件通过 Hook 读取/写入状态。
- 组件不直接访问 `localStorage`，由 Provider 统一处理持久化。
- 读取不到 Provider 上下文时，应抛出明确错误，避免静默失败。

## 持久化

- 允许在 Provider 内对用户偏好类状态进行 `localStorage` 持久化。
- 需要跨标签页同步时，监听 `storage` 事件并做状态对齐。
- 涉及敏感信息的状态不得写入本地持久化存储。

## Store 拆分原则

- 按业务域拆分 Provider（主题、字号、身份等），避免单一超大 Context。
- 高频变更状态与低频配置状态分离，减少无效重渲染。
