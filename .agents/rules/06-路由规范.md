# 路由规范（NON-NEGOTIABLE）

## 路由结构

项目使用 Next.js App Router 文件路由：

```text
src/app/
├── page.tsx                 # 首页
├── layout.tsx               # 根布局
├── skills/
│   ├── page.tsx
│   └── [slug]/page.tsx
├── rules/
│   ├── page.tsx
│   └── [slug]/page.tsx
└── api/**/route.ts          # API 路由处理器
```

## 懒加载（NON-NEGOTIABLE）

- 路由级按文件系统天然分割，不额外维护集中式路由表。
- 页面加载态通过同目录 `loading.tsx` 管理。
- 动态路由参数通过目录段 `[param]` 声明。

## 路由 Meta 规范

- 当前项目未采用独立 `meta` 对象约定（非 `vue-router` 模式）。
- SEO 与页面元信息优先通过 `metadata` 与页面/布局导出进行管理。

## App Router 关键约束（NON-NEGOTIABLE）

- `src/app/**` 下组件默认是 Server Component；默认不得直接使用浏览器 API 与 React 客户端 hooks。
- 仅在需要交互、状态 hooks、DOM API 时，才在文件顶部显式添加 `"use client"`。
- 页面缓存策略需显式评估：按需求设置 `dynamic`、`revalidate` 或 `fetch` 缓存参数，避免默认缓存误用。
- 元信息生成使用 `metadata` / `generateMetadata`，并保持服务端语义，不在客户端组件中处理 SEO 元信息。

## 导航守卫

- 当前项目未采用前端全局导航守卫模式。
- 权限与访问控制优先通过 `middleware.ts` + 服务端鉴权逻辑实现。
- 涉及后台或敏感页面时，必须在服务端再次鉴权，不能只依赖前端跳转限制。

## 约束

- 页面必须放在 `src/app/**/page.tsx`。
- API 必须放在 `src/app/api/**/route.ts`，按资源语义组织目录层级。
- 新增动态页面时，目录命名与参数命名需保持业务语义清晰（如 `[slug]`、`[id]`）。
