# Proposal: AgentHub 多主题切换系统 — 像素/Apple/手绘三风格无刷新切换

## Why

当前 AgentHub 仅支持单一像素风格，用户无法根据个人喜好或使用场景切换主题。为提升用户体验和平台灵活性，需要实现：
- **多主题支持**：像素风（游戏怀旧）、Apple 风（现代简约）、手绘风（温馨创意）
- **无刷新切换**：切换过程丝滑流畅，无需页面刷新
- **主题配置化**：主题代码独立配置文件，易于扩展和维护
- **持久化记忆**：用户偏好自动保存，下次访问自动应用

多主题系统将显著提升 AgentHub 的视觉吸引力和用户满意度。

## What Changes

- **主题配置文件**：独立主题配置模块（`src/themes/`），每个主题独立文件
- **CSS 变量系统**：基于 CSS 变量的主题切换（高性能、无刷新）
- **主题切换器组件**：顶部导航栏增加主题切换按钮（下拉菜单 + 预览）
- **本地存储**：用户主题偏好 localStorage 持久化
- **过渡动画**：主题切换平滑过渡（300ms ease-in-out）
- **三款主题设计**：
  - **像素风**（Pixel）：游戏怀旧风格（当前主题，保留）
  - **Apple 风**（Modern）：现代简约，类似 Apple 官网
  - **手绘风**（Sketch）：温馨创意，手绘质感

## Capabilities

### New Capabilities

- `theme-system`: 多主题切换能力，支持 3+ 主题无刷新切换
- `theme-config`: 主题配置化能力，每个主题独立配置文件
- `theme-switcher`: 主题切换器 UI 组件，支持预览和快速切换
- `theme-persistence`: 主题偏好持久化能力（localStorage）
- `smooth-transition`: 平滑过渡动画能力（300ms，无卡顿）

### Modified Capabilities

- `pixel-ui-system`: 从唯一主题改为多主题之一，保持原有功能
- `responsive-design`: 扩展为多主题响应式适配

## Impact

- **CSS 架构**: 引入 CSS 变量系统，所有颜色/字体/边框使用变量
- **组件库**: 所有组件需支持主题变量（无硬编码颜色）
- **性能**: 主题切换无刷新，性能开销 < 50ms
- **存储**: localStorage 增加 `preferred-theme` 字段
- **打包**: 主题配置文件独立打包（按需加载或全量预加载）
- **可维护性**: 主题代码集中管理，易于扩展新主题

## Non-Goals（本次不做）

- 深色/浅色模式自动切换（后续迭代）
- 主题编辑器（用户自定义主题，后续迭代）
- 主题市场（用户分享主题，后续迭代）
- 按页面/组件级主题（全局统一主题，后续迭代）

## Success Criteria

- ✅ 三款主题完整实现（像素/Apple/手绘）
- ✅ 主题切换无刷新，切换时间 < 300ms
- ✅ 切换过程丝滑流畅，无闪烁、无卡顿
- ✅ 主题配置独立文件（`src/themes/*.ts`）
- ✅ 用户偏好持久化（刷新后保持）
- ✅ 所有组件正确应用主题（无硬编码颜色）
- ✅ 移动端完全可用
- ✅ 主题切换器 UI 美观易用
- ✅ 代码复用率高（>80% 样式复用）

## Dependencies

- **依赖于**: `agenthub-dual-platform`（双轨制平台）
- **不影响**: 现有功能（Skill/Rule 管理、搜索、评测等）
- **可并行**: 可在双轨制开发完成后独立开发

## Risks

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| **主题切换闪烁** | 中 | 使用 CSS 变量 + `document.startViewTransition()` API |
| **样式遗漏** | 中 | 建立样式审查清单，E2E 测试覆盖所有页面 |
| **性能下降** | 低 | 主题配置预加载，避免运行时计算 |
| **移动端适配复杂** | 低 | 每个主题单独测试移动端，使用响应式变量 |
