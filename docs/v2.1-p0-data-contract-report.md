# V2.1 P0 数据模型与契约保护实施报告

## 1. P0 目标

V2.1 P0 的目标是先把 Hub API(Hub 接口) 对 br-ai-spec(本地 CLI 与协议工具) 的消费契约固化下来，并为后续 Asset(资产)、Manifest(清单)、Agent Profile(智能体画像) 治理准备最小数据结构。

本轮不进入 UI(用户界面)、复杂审核流、Asset Factory(资产工厂)、OpenClaw、钉钉机器人、自动 PR / push / merge(自动提交合并) 等能力，只保护 V1.1 已经可用的 Hub 最小闭环：

- Manifest Recommend API(清单推荐接口)
- Manifest Export API(清单导出接口)
- Asset Content API(资产内容接口)
- Agent Profile Export API(智能体画像导出接口)
- Install Record API(安装记录接口)
- Runtime Feedback API(运行反馈接口)

## 5. 是否影响 V1.1 Hub API

不影响 V1.1 Hub API(Hub 接口)路径和既有响应结构。

已保护 API：

```http
POST /api/hub/manifests/recommend
GET /api/hub/manifests/:slug/export
GET /api/hub/assets/:slug/content
GET /api/hub/agent-profiles/:slug/export
POST /api/hub/install-records
POST /api/hub/runtime-feedback
```

保护点：

- ApiResponse(统一响应)仍包含 `success` / `data` / `error` / `requestId` / `timestamp`。
- error(错误对象)仍包含 `code` / `message` / `suggestion`。
- Manifest Export(清单导出)仍包含 `assets`。
- Manifest Export(清单导出)仍包含 `agentProfiles`。
- Asset Content(资产内容)仍包含 `content` 和 `checksum`。
- Agent Profile Export(智能体画像导出)仍包含 `content` 和 `checksum`。
- Install Record(安装记录)不接收 `sourceCode`。
- Runtime Feedback(运行反馈)不接收 `rawPrompt` / `rawResponse` / 绝对路径 / `sourceCode`。

## 7. published 不可变策略验证

新增 `tests/unit/assets/asset-version-immutability.test.ts` 和 `tests/unit/manifests/manifest-published-only.test.ts`。

已验证：

- published(已发布) AssetVersion(资产版本)不允许直接修改 `content`。
- draft(草稿) AssetVersion(资产版本)允许修改 `content`。
- 修改 draft(草稿)内容后会重新计算 `checksum` 和 `contentSize`。
- 修改 published(已发布)内容必须创建新版本。
- published(已发布) AssetVersion(资产版本)必须具备 `immutable=true`。
- published(已发布) AssetVersion(资产版本)必须具备 `checksum`。
- archived(已归档) AssetVersion(资产版本)不允许新绑定到 Manifest(清单)。
- deprecated(已废弃) AssetVersion(资产版本)不应新绑定到 Manifest(清单)。
