## 5. Asset 创建规则

`POST /api/hub/admin/assets` 支持创建 draft(草稿) Asset(资产)。

规则：

- `slug` 必填且唯一。
- `name` 必填。
- `kind` 必填，支持 `rule` / `skill` / `role` / `flow` / `scenario` / `agent-profile` / `tech-profile` / `source-pack` / `contract`。
- `scope` 必填，支持 `platform` / `department` / `team` / `project` / `personal`。
- 默认 `status=draft`。
- 创建时不允许直接 published(已发布)。
- 重复 `slug` 返回 `ASSET_SLUG_ALREADY_EXISTS`。
- 非法 `kind` 返回 `INVALID_ASSET_KIND`。
- 请求中不允许出现 `sourceCode`、`rawPrompt`、`rawResponse`、绝对路径。

## 6. Asset 更新规则

`PATCH /api/hub/admin/assets/:assetId` 支持更新 draft(草稿) / rejected(已驳回) Asset(资产)基础信息。

规则：

- 只允许更新 `name`、`description`、`tags`、`visibility`、`ownerTeamId`、`ownerUserId`。
- 不允许修改 `slug`。
- 不允许修改 `kind`。
- 不允许传入 `content`。
- published(已发布)、deprecated(已废弃)、archived(已归档)资产不允许直接修改基础信息。
- archived(已归档)资产返回 `ASSET_ARCHIVED`。
- 其他状态不允许更新返回 `ASSET_UPDATE_NOT_ALLOWED`。

## 7. Asset Version 创建规则

`POST /api/hub/admin/assets/:assetId/versions` 支持创建 draft(草稿) AssetVersion(资产版本)。

规则：

- Asset(资产)必须存在。
- 同一 Asset(资产)下 `version` 必须唯一。
- `content` 必填。
- `contentFormat` 默认 `markdown`，支持 `markdown` / `json` / `yaml`。
- 新建版本默认 `status=draft`。
- 新建版本默认 `immutable=false`。
- 自动生成 `checksum`。
- 自动计算 `contentSize`。
- 不允许覆盖已存在 version(版本)。
- archived(已归档) Asset(资产)不允许新增版本。

## 8. Asset Version 发布规则

`POST /api/hub/admin/assets/:assetId/versions/:versionId/publish` 支持发布 draft(草稿) / reviewing(审核中)版本。

规则：

- 只能发布 draft(草稿) / reviewing(审核中)状态版本。
- `content` 不能为空。
- 发布时重新计算 `checksum`。
- 发布后 `status=published`。
- 发布后 `immutable=true`。
- 写入 `publishedAt`。
- 写入 `publishedBy=system`。
- 更新 `Asset.latestVersionId`。
- 更新 `Asset.status=published`。
- published(已发布)后不允许修改 content(正文)。

## 9. Asset Version 废弃规则

`POST /api/hub/admin/assets/:assetId/versions/:versionId/deprecate` 支持废弃 published(已发布)版本。

规则：

- 只能废弃 published(已发布)版本。
- deprecated(已废弃)版本不删除 content(正文)。
- deprecated(已废弃)版本不改变 checksum(校验和)。
- deprecated(已废弃)版本可供旧 lock(锁文件)继续使用，但不应被新 Manifest(清单)默认绑定。
- 非 published(已发布)版本返回 `ASSET_VERSION_DEPRECATE_NOT_ALLOWED`。

## 10. Asset 归档规则

`POST /api/hub/admin/assets/:assetId/archive` 支持归档 Asset(资产)。

规则：

- archived(已归档)后 Asset(资产)不允许新增版本。
- archived(已归档)后 Asset(资产)不允许修改。
- archived(已归档)后不允许新 Manifest(清单)绑定。
- 不删除历史版本。
- 不删除 content(正文)。
- 写入 `archivedAt`。

## 11. published 不可变策略

published(已发布)不可变策略：

- 发布时 `immutable=true`。
- 发布后 `status=published`。
- 发布后 AssetService(资产服务)禁止直接修改 content(正文)。
- 发布后如需修改正文，必须创建新的 AssetVersion(资产版本)。
- API(API 接口)测试覆盖 published(已发布)版本不允许修改 content(正文)。

## 12. checksum 策略

checksum(校验和)策略：

- 创建 AssetVersion(资产版本)时自动生成 `sha256:` 前缀 checksum(校验和)。
- 创建 AssetVersion(资产版本)时自动计算 `contentSize`。
- 发布 AssetVersion(资产版本)时重新计算 checksum(校验和)。
- deprecated(已废弃)版本不改变 checksum(校验和)。
- 列表和详情接口均返回 checksum(校验和)。
- 列表接口不返回完整 content(正文)。

## 18. 风险点

风险点：

- 当前新增 Asset 管理 API(API 接口)基于现有内存 HubRepository(Hub 仓储)，数据库持久化仓储仍需后续阶段补齐。
- 当前发布流程是最小状态流，不包含复杂审核人、审核记录和多级审批。
- `deprecate` 目前更新版本 `status=deprecated` 并保留 checksum(校验和)，P0 schema(模型定义)未给 AssetVersion(资产版本)单独提供 `deprecatedAt` 字段。
- lint(代码规范检查)仍存在历史 warning(警告)，但本轮未新增 error(错误)。
- `.next/dev/types/routes.d.ts` 是本地生成缓存，执行 `npx next typegen` 后 TypeScript(类型检查)通过。
