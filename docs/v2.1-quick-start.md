# V2.1 Quick Start

## 1. V2.1 能力说明

V2.1 将 skill-q-platform 从 Hub API(资产中心接口) 最小闭环升级为团队可操作的资产治理平台，当前包含：

- Asset(资产) 管理 API(应用程序接口) 与页面。
- Manifest(清单) 管理 API(应用程序接口) 与页面。
- Agent Profile(智能体配置) 管理 API(应用程序接口) 与页面。
- Install Record(安装记录) 只读页面。
- Runtime Feedback(运行反馈) 只读页面。
- 发布流程与审核占位。
- V1.1 Hub API(资产中心接口) 兼容保护。
- br-ai-spec(规范工具) Hub 契约兼容测试。

V2.1 不包含 AI 工程资产生成器、真实 Codex(代码智能体) 自动编码、OpenClaw(开放执行器)、钉钉机器人、复杂 RBAC(基于角色的访问控制) 和复杂组织架构。

- Hub(资产中心) 首页：`/hub`
- Asset(资产) 列表：`/hub/assets`
- Asset(资产) 详情：`/hub/assets/[id]`

- Install Record(安装记录)：`/hub/install-records`
- Runtime Feedback(运行反馈)：`/hub/runtime-feedback`

## 4. Asset 管理快速流程

1. 进入 `/hub/assets`。
2. 点击“创建草稿”，输入 Asset slug(资产标识) 与名称。
3. 进入 Asset(资产) 详情页。
4. 点击“创建版本”，输入 version(版本号) 与 content(正文)。
5. 对 draft(草稿) 或 rejected(已驳回) 版本点击“提交审核”。
6. 对 reviewing(审核中) 版本点击“审核通过发布”。
7. published(已发布) 版本会显示不可修改提示；如需调整正文，请创建新版本。
8. 如资产不再使用，可执行“废弃”或“归档”。

## 5. Manifest 管理快速流程

1. 进入 `/hub/manifests`。
2. 点击“创建草稿”，输入 Manifest slug(清单标识) 与名称。
3. 进入 Manifest(清单) 详情页。
4. 创建 Manifest Version(清单版本)。
5. 绑定已发布的 AssetVersion(资产版本)。
6. 对 draft(草稿) 或 rejected(已驳回) 版本提交审核。
7. 对 reviewing(审核中) 版本审核通过发布。
8. 发布前必须至少绑定一个 required asset(必需资产)。
9. published(已发布) 后不允许解绑或调整绑定顺序。

## 6. Agent Profile 管理快速流程

1. 进入 `/hub/agent-profiles`。
2. 点击“创建草稿”，创建 Agent Profile(智能体配置)。
3. 进入详情页查看 content(内容)、deniedTools(禁用工具)、contextScope(上下文范围)、approvalPolicy(审批策略)。
4. 点击“校验安全策略”。
5. 安全策略通过后提交审核。
6. reviewing(审核中) 状态可审核通过发布或驳回。
7. published(已发布) 后不允许直接修改 content(内容)。

默认安全策略：

- 禁止 upload-source(上传源码)。
- 禁止 deploy(部署)。
- 禁止 push(推送)。
- 禁止 merge(合并)。
- 禁止 allowSourceCode(允许源码)。
- 禁止 allowAbsolutePath(允许绝对路径)。

## 7. 审核流程快速流程

状态流转：

```text
draft -> reviewing
reviewing -> published
reviewing -> rejected
rejected -> reviewing
published -> deprecated
published -> archived
deprecated -> archived
```

操作规则：

- draft/rejected 可提交审核。
- reviewing 可驳回。
- reviewing 可审核通过发布。
- 驳回必须填写 reason(原因)。
- 状态变更会写入 AuditLog(审计日志) 占位。
- AuditLog(审计日志) 当前为内存占位，可通过 `GET /api/hub/admin/audit-logs` 查询。

## 8. Install Record 查看方式

进入 `/hub/install-records` 查看 br-ai-spec init --yes 上报记录。

支持：

- manifestSlug(清单标识) 搜索。
- status(状态) 筛选。
- 分页展示。

原有 `POST /api/hub/install-records` 契约不变。

## 9. Runtime Feedback 查看方式

进入 `/hub/runtime-feedback` 查看 br-ai-spec runtime-feedback(运行反馈) 上报记录。

支持：

- manifestSlug(清单标识) 搜索。
- success(是否成功) 筛选。
- executorType(执行器类型) 筛选。
- 分页展示。

原有 `POST /api/hub/runtime-feedback` 契约不变，仍拒绝 sourceCode(源码)、rawPrompt(原始提示)、rawResponse(原始响应) 和绝对路径。

## 10. 常见问题

### 为什么 publish(发布) API 仍兼容 draft 直接发布？

为保护 P1/P2/P3 已有 API(应用程序接口) 调用和回归测试，服务端暂时保留 draft 直接发布兼容。P5 页面主路径已经调整为先 submit-review(提交审核)，再 publish(发布)。后续若要强制审核后发布，应单独收紧契约并同步迁移测试。

### 页面 smoke test(冒烟测试) 是否使用真实浏览器？

当前使用现有 Vitest(测试框架) + React Testing Library(React 测试库) 方式验证页面组件可渲染、错误态/空状态/敏感字段不展示。`npm run build` 也验证了 Next.js(框架) 路由可被构建识别。

### 审计日志是否持久化？

当前不是持久化表，是内存占位。生产化需要新增 AuditLog(审计日志) 表和 migration(数据库迁移)。
