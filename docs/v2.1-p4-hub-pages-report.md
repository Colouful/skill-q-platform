# V2.1 P4 Hub 页面实施报告

## 1. P4 目标

V2.1 P4 目标是把 skill-q-platform 从“只有 API(应用程序接口) 的 Hub(资产中心) 后台”升级为“可操作的资产治理页面”，在不修改 br-ai-spec、不修改 br-ai-spec-visual、不新增依赖、不修改 Prisma schema(Prisma 数据模型定义) 的前提下，为 Asset(资产)、Manifest(清单)、Agent Profile(智能体配置)、Install Record(安装记录)、Runtime Feedback(运行反馈) 提供基础页面入口、列表、详情、状态展示、操作确认、错误态、空状态和加载态。

## 2. 修改范围

- 新增 `/hub` 及其子页面。
- 新增 Hub(资产中心) 页面复用组件。
- 新增前端 API(应用程序接口) client(客户端) 封装。
- 新增 Install Record(安装记录) 和 Runtime Feedback(运行反馈) 只读 admin(后台管理) 查询 API(应用程序接口)。
- 更新顶部导航，增加“资产治理”入口。
- 为 Manifest(清单) admin(后台管理) 绑定关系序列化补充 `manifestVersionId`，用于页面解绑和排序操作。
- 新增页面 smoke test(冒烟测试)、组件测试和 API(应用程序接口) client(客户端) 测试。

未修改 Prisma schema(Prisma 数据模型定义)，未新增 migration(数据库迁移)，未修改根目录 `package.json`。

## 5. 新增前端 API client 列表

新增 `src/lib/hub-admin-client.ts`，封装：

- Asset(资产)：`listAssets`、`createAsset`、`getAssetDetail`、`updateAsset`、`createAssetVersion`、`publishAssetVersion`、`deprecateAssetVersion`、`archiveAsset`
- Manifest(清单)：`listManifests`、`createManifest`、`getManifestDetail`、`updateManifest`、`createManifestVersion`、`bindManifestAsset`、`unbindManifestAsset`、`reorderManifestAssets`、`publishManifestVersion`、`deprecateManifestVersion`、`archiveManifest`
- Agent Profile(智能体配置)：`listAgentProfiles`、`createAgentProfile`、`getAgentProfileDetail`、`updateAgentProfile`、`publishAgentProfile`、`deprecateAgentProfile`、`archiveAgentProfile`、`validateAgentProfile`
- Install Record(安装记录)：`listInstallRecords`
- Runtime Feedback(运行反馈)：`listRuntimeFeedback`

client(客户端) 统一解析 ApiResponse(统一响应结构)，失败时优先使用后端中文 `message` 和 `suggestion`。

## 6. Asset 页面能力

- Asset(资产) 列表支持 keyword(关键词)、kind(类型)、status(状态)、scope(范围)、分页查询。
- Asset(资产) 列表展示 slug(标识)、name(名称)、kind(类型)、scope(范围)、status(状态)、visibility(可见性)、版本数量、已发布版本数量、latestVersionId(最新版本标识)、updatedAt(更新时间)。
- 支持创建 Asset(资产) 草稿、进入详情、创建版本、发布版本、废弃版本、归档资产。
- Asset(资产) 详情展示基础信息、版本列表、manifestRefs(清单引用)、checksum(校验和) 和 published(已发布) 不可变提示。
- 页面不展示完整 content(正文)，仅在版本详情弹窗中只读展示。

## 7. Manifest 页面能力

- Manifest(清单) 列表支持 keyword(关键词)、status(状态)、scope(范围)、techStack(技术栈)、projectKind(项目类型)、分页查询。
- Manifest(清单) 列表展示 slug(标识)、name(名称)、scope(范围)、status(状态)、techStacks(技术栈)、projectKinds(项目类型)、版本数量、已发布版本数量、绑定数量、latestVersionId(最新版本标识)、updatedAt(更新时间)。
- 支持创建 Manifest(清单) 草稿、创建 Manifest Version(清单版本)、查看版本详情、绑定 AssetVersion(资产版本)、解绑、调整顺序、发布、废弃、归档。
- Manifest Version(清单版本) 详情不返回 AssetVersion(资产版本) 正文。
- 页面提示 Manifest Export(清单导出) 继续保持 br-ai-spec(规范工具) 可消费结构。

## 8. Agent Profile 页面能力

- Agent Profile(智能体配置) 列表支持 keyword(关键词)、status(状态)、riskLevel(风险等级)、defaultExecutor(默认执行器)、分页查询。
- Agent Profile(智能体配置) 列表展示 slug(标识)、name(名称)、version(版本)、status(状态)、riskLevel(风险等级)、defaultExecutor(默认执行器)、deniedTools(禁用工具)、checksum(校验和)、updatedAt(更新时间)。
- 支持创建草稿、查看详情、发布、废弃、归档和安全策略校验。
- 详情页突出展示禁止上传源码、禁止 push(推送)、禁止 merge(合并)、禁止 deploy(部署)、禁止绝对路径、提交前人工确认、合并前人工确认、高风险强制人工确认。
- content(内容) 只读展示，不展示敏感字段。

## 9. Install Record 页面能力

- 新增 `/hub/install-records` 页面。
- 支持 manifestSlug(清单标识)、status(状态)、分页查询。
- 展示 projectId(项目标识)、workspaceId(工作区标识)、manifestSlug(清单标识)、manifestVersion(清单版本)、status(状态)、packageCount(包数量)、clientName(客户端名称)、clientVersion(客户端版本)、installedAt(安装时间)、createdAt(创建时间)。
- 新增只读查询 API(应用程序接口)：`GET /api/hub/admin/install-records`。
- 原有 `POST /api/hub/install-records` 契约不变。

## 10. Runtime Feedback 页面能力

- 新增 `/hub/runtime-feedback` 页面。
- 支持 manifestSlug(清单标识)、success(是否成功)、executorType(执行器类型)、分页查询。
- 展示 projectId(项目标识)、runId(运行标识)、manifestSlug(清单标识)、manifestVersion(清单版本)、success(是否成功)、durationMs(耗时)、executorType(执行器类型)、failureCategory(失败分类)、privacyChecked(隐私校验)、createdAt(创建时间)。
- 新增只读查询 API(应用程序接口)：`GET /api/hub/admin/runtime-feedback`。
- 原有 `POST /api/hub/runtime-feedback` 契约不变。

## 11. 页面错误态、空状态、加载态说明

- 加载态统一显示中文加载提示。
- 空状态统一使用 `EmptyState` 展示中文说明和下一步操作提示。
- 错误态统一使用 `ErrorState` 展示中文错误信息。
- 关键操作使用确认机制；P4 当前使用浏览器 confirm(确认弹窗) 和 prompt(输入弹窗) 作为最小可用交互，P5 可替换为更完整的受控弹窗和审核占位流程。

## 12. 是否影响 V1.1 Hub API

不影响。以下 V1.1 Hub(资产中心) API(应用程序接口) 路径和响应契约保持不变：

- `POST /api/hub/manifests/recommend`
- `GET /api/hub/manifests/:slug/export`
- `GET /api/hub/assets/:slug/content`
- `GET /api/hub/agent-profiles/:slug/export`
- `POST /api/hub/install-records`
- `POST /api/hub/runtime-feedback`

契约回归测试通过。

## 13. 是否影响 P1 Asset 管理 API

不影响。P1 Asset(资产) 管理 API(应用程序接口) 回归测试通过。P4 页面通过现有 admin(后台管理) API(应用程序接口) 调用，不修改 Asset(资产) 服务规则。

## 14. 是否影响 P2 Manifest 管理 API

不影响。P2 Manifest(清单) 管理 API(应用程序接口) 回归测试通过。仅在 admin(后台管理) 绑定关系序列化中补充 `manifestVersionId`，用于页面调用解绑和排序 API(应用程序接口)，不影响 V1.1 Manifest Export(清单导出) 契约。

## 15. 是否影响 P3 Agent Profile 管理 API

不影响。P3 Agent Profile(智能体配置) 管理 API(应用程序接口) 回归测试通过。P4 页面通过既有 validate(校验)、publish(发布)、deprecate(废弃)、archive(归档) API(应用程序接口) 调用。

## 19. 风险点

- P4 页面当前依赖 P1/P2/P3 admin(后台管理) API(应用程序接口) 的字段稳定性；如果后续接口字段调整，需要同步更新 `hub-admin-client.ts`。
- Install Record(安装记录) 和 Runtime Feedback(运行反馈) 当前只做只读列表，不包含复杂报表和聚合统计。
- 页面创建与绑定操作为最小可用表单，适合 P4 阶段验证治理闭环，P5 需要补充更严格的发布审核体验。

## 20. 是否可以进入 V2.1 P5 发布流程与审核占位

可以进入 V2.1 P5。P4 已提供 Hub(资产中心) 页面入口、资产治理主要页面、前端 API(应用程序接口) client(客户端)、只读运行数据页面和回归测试基础，下一阶段可以在现有页面上补充发布流程、审核占位和更完整的操作弹窗。
