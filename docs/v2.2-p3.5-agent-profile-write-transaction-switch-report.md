# V2.2 P3.5 Agent Profile 写事务切换 Prisma Repository 实施报告

## 1. P3.5 目标

本轮目标是把 Agent Profile(智能体画像) 的创建、更新、发布、废弃、归档写事务接入 Repository Port(仓储端口) 与 TransactionManager(事务管理器)，支持 `HUB_REPOSITORY_MODE=memory` 和 `HUB_REPOSITORY_MODE=prisma` 双模式。

本轮不做 Review Workflow(审核流程) 全局事务化，不切换 Asset(资产) 和 Manifest(清单) 写事务，不修改 br-ai-spec(规范消费端) 和 br-ai-spec-visual(运行态可视化)。

## 2. 修改范围

- 让默认 memory(内存) 写事务和默认 AuditLogService(审计日志服务) 共享同一个 InMemory Adapter(内存适配器)，保证路由级发布审计可查询。

## 4. Agent Profile 创建切换说明

创建逻辑继续保持：

- `slug`、`name`、`version` 必填。
- `slug + version` 唯一。
- 默认 `status=draft`。
- 不允许创建时直接 `published`。
- 创建前执行隐私校验，不允许 `sourceCode`、`rawPrompt`、`rawResponse`、绝对路径。
- 创建时补齐默认安全策略。
- 自动计算 checksum(校验和)。

memory(内存) 模式通过 InMemoryHubRepositoryAdapter 写入；prisma(数据库) 模式通过 PrismaAgentProfileRepository 写入。

## 5. Agent Profile 更新切换说明

更新逻辑继续保持：

- 只允许 `draft / rejected` 状态更新。
- `published / deprecated / archived` 不允许直接更新。
- 不允许修改 `slug`。
- 不允许修改 `version`。
- content(内容) 变更时重新执行安全策略校验。
- content(内容) 变更时重新计算 checksum(校验和)。
- `rejected` 更新后回到 `draft`。

## 6. Agent Profile 发布事务说明

Agent Profile 发布通过 TransactionManager(事务管理器) 执行，并在同一事务内完成：

1. 查询 Agent Profile。
2. 校验状态只允许 `draft / reviewing`。
3. 校验 content(内容) 存在。
4. 校验 checksum(校验和) 存在。
5. 校验安全策略。
6. 重新计算 checksum(校验和)。
7. 更新 `status=published`。
8. 写入 `publishedAt / publishedBy`。
9. 写入 AuditLog(审计日志)，`targetType=agent-profile`，`action=publish`。

如果安全策略失败、业务写入失败或 AuditLog(审计日志) 写入失败，事务整体回滚。

## 7. Agent Profile 废弃切换说明

废弃逻辑继续保持：

- 只能废弃 `published` 状态。
- 不删除 content(内容)。
- 不改变 checksum(校验和)。
- 写入 AuditLog(审计日志)，`action=deprecate`。

## 8. Agent Profile 归档切换说明

归档逻辑继续保持：

- 归档后不允许修改。
- 不删除 content(内容)。
- 不改变 checksum(校验和)。
- 写入 `archivedAt`。
- 写入 AuditLog(审计日志)，`action=archive`。

## 9. 安全策略事务一致性说明

发布前继续强制校验：

- `deniedTools` 必须包含 `upload-source`。
- `deniedTools` 必须包含 `deploy`。
- `deniedTools` 必须包含 `push`。
- `deniedTools` 必须包含 `merge`。
- `contextScope.allowSourceCode=false`。
- `contextScope.allowAbsolutePath=false`。
- `approvalPolicy.beforePush=true`。
- `approvalPolicy.beforeMerge=true`。
- `approvalPolicy.highRiskAlwaysManual=true`。

安全策略不通过时，Agent Profile 状态不会变更，AuditLog(审计日志) 不会写入。

## 10. AuditLog 一致性说明

Agent Profile 发布、废弃、归档在事务上下文中写入 AuditLog(审计日志)。

本轮同时修复默认 memory(内存) 路由审计查询一致性：默认 TransactionManager(事务管理器) 和默认 AuditLogService(审计日志服务) 共享同一个 InMemory Adapter(内存适配器)，避免发布成功后 `/api/hub/admin/audit-logs` 查询不到审计记录。

## 11. memory 模式行为

- Agent Profile 读写都走 InMemoryHubRepositoryAdapter(内存 Hub 仓储适配器)。
- 不需要 Prisma Client(Prisma 客户端)。
- 单元测试和本地快速验证默认使用该模式。

## 12. prisma 模式行为

- Agent Profile 读写都走 Prisma Repository(Prisma 仓储)。
- 通过 PrismaTransactionManager(Prisma 事务管理器) 使用 `prisma.$transaction`。
- 缺少 Prisma Client(Prisma 客户端) 时返回中文错误，不静默降级到 memory(内存)。
