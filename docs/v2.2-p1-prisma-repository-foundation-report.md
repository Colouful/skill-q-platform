# V2.2 P1 Prisma Repository 基础设施实施报告

## 1. P1 目标

V2.2 P1 的目标是为 Hub(资产中心) 生产化持久化打基础，只做 Repository Port(仓储接口) 与 Repository Adapter(仓储适配器) 基础设施：

1. 抽出 Repository Port(仓储接口)。
2. 保留 InMemory Repository(内存仓储) 作为测试实现。
3. 新增 Prisma Repository(Prisma 数据库仓储) 基础实现。
4. 新增 Repository Factory(仓储工厂)。
5. 新增 Repository Mapper(仓储映射器)。
6. 新增 Repository Contract Test(仓储契约测试)。
7. 不直接切换 V2.1 已完成的 P1 / P2 / P3 / P5 业务服务。

## 2. 修改范围

本轮只新增和修改以下范围：

1. `src/server/hub/repositories/`：新增仓储接口、内存适配器、Prisma(数据库 ORM) 适配器、Mapper(映射器)、Factory(工厂)。
2. `tests/unit/repositories/`：新增仓储基础设施单元测试和契约测试。
3. `docs/v2.2-p1-prisma-repository-foundation-report.md`：新增 P1 实施报告。

本轮未修改：

1. Prisma schema(数据库结构定义)。
2. migration(数据库迁移)。
3. 根目录 `package.json`(包配置)。
4. V1.1 Hub API(资产中心接口)。
5. V2.1 页面。
6. P1 / P2 / P3 / P5 业务服务调用链。

## 3. 新增 Repository Port 列表

新增 Port(接口)：

1. `AssetRepositoryPort`：Asset(资产) 列表、详情、slug 查询、版本列表、版本详情。
2. `ManifestRepositoryPort`：Manifest(清单) 列表、详情、slug 查询、版本列表、版本详情、资产绑定列表。
3. `AgentProfileRepositoryPort`：Agent Profile(智能体配置) 列表、详情、slug + version 查询。
4. `TelemetryRepositoryPort`：Install Record(安装记录) 和 Runtime Feedback(运行反馈) 查询。
5. `AuditLogRepositoryPort`：AuditLog(审计日志) 查询和创建接口占位。
6. `HubRepositoryPort`：组合以上仓储接口，作为后续 service(服务) 切换的统一依赖。

## 4. 新增 Repository Adapter 列表

新增 Adapter(适配器)：

1. `InMemoryHubRepositoryAdapter`：包装当前 `HubRepository` 内存实现，供测试和过渡使用。
2. `PrismaHubRepository`：Prisma Repository(Prisma 数据库仓储) 门面。
3. `PrismaAssetRepository`：Asset 查询基础实现。
4. `PrismaManifestRepository`：Manifest 查询基础实现。
5. `PrismaAgentProfileRepository`：Agent Profile 查询基础实现。
6. `PrismaTelemetryRepository`：Install Record / Runtime Feedback 查询基础实现。

## 5. InMemory Repository 保留策略

InMemory Repository(内存仓储) 继续保留，原因：

1. V2.1 大量单元测试依赖内存 fixture(测试夹具) 快速构造数据。
2. P1 不切换业务服务，保留当前运行路径稳定。
3. 后续 P3 切换 Prisma Repository(Prisma 数据库仓储) 时，可用同一组 contract test(契约测试) 对比内存实现和 Prisma 实现。
4. 本地演示仍可通过 memory(内存) 模式运行，避免没有数据库连接时阻断前端联调。

## 6. Prisma Repository 实现范围

本轮 Prisma Repository(Prisma 数据库仓储) 只实现基础查询能力和 AuditLog(审计日志) 占位：

1. Asset 列表、详情、slug 查询、版本列表、版本详情。
2. Manifest 列表、详情、slug 查询、版本列表、版本详情、绑定列表。
3. Agent Profile 列表、详情、slug + version 查询。
4. Install Record 查询。
5. Runtime Feedback 查询。
6. 基础分页。
7. 基础 keyword(关键词) 搜索。
8. 基础 status(状态)、kind(类型)、riskLevel(风险等级) 筛选。

暂未实现：

1. 发布事务。
2. 审核事务。
3. Manifest Asset(清单资产) 绑定、解绑、排序事务。
4. AuditLog 持久化写入。
5. 真实数据库集成测试。

这些内容按 V2.2 方案放到 P2 / P3 / P7。

## 7. Repository Factory 说明

新增 `createHubRepositoryProvider`，支持两种模式：

1. `memory`：默认模式，创建 `InMemoryHubRepositoryAdapter`。
2. `prisma`：创建 `PrismaHubRepository`，要求显式注入 Prisma Client(Prisma 客户端)。

设计边界：

1. 默认模式为 memory，避免破坏现有测试。
2. prisma 模式缺少 Prisma Client 时返回中文错误。
3. 未知 `HUB_REPOSITORY_MODE` 返回中文错误。
4. 本轮不在业务 service(服务) 中散落 Prisma Client 调用。

## 8. Mapper 说明

新增 `prisma-mappers.ts`，负责将 Prisma(数据库 ORM) 原始对象转换为 V2.1 兼容的数据结构。

Mapper(映射器) 保障：

1. Date(日期) 转为 ISO 字符串。
2. Json(JSON 数据) 字段安全解析。
3. Asset / Manifest / Agent Profile 列表结构与 V2.1 兼容。
4. Install Record / Runtime Feedback 列表结构与 V2.1 兼容。
5. 不返回 `sourceCode`。
6. 不返回 `sourceContent`。
7. 不返回 `fileContent`。
8. 不返回 `rawPrompt`。
9. 不返回 `rawResponse`。
10. 不返回绝对路径。
11. 不返回 `password` / `token` / `secret` / `apiKey`。
12. checksum(校验和) 字段保持原值，不在 mapper 中重新生成。
13. published(已发布) / immutable(不可变) 状态语义不变。

## 9. 当前是否切换业务服务

## 18. 风险点

1. Prisma Repository(Prisma 数据库仓储) 当前只做基础查询，后续 P3 切换 service(服务) 时需要逐步替换内存数组访问。
2. Json(JSON 数据) 查询条件中 `array_contains` 需要在真实 MySQL / MariaDB(关系型数据库) 环境验证兼容性。
3. AuditLog(审计日志) 当前 Prisma 写入为中文错误占位，必须在 P2 落持久化。
4. Agent Profile(智能体配置) Prisma 模型当前没有 rejectedAt / rejectedReason，P2/P3 需要确认是否补字段或只依赖 AuditLog。
5. Repository Factory(仓储工厂) 的 prisma 模式目前要求显式注入 Prisma Client，后续接入运行时 provider(提供者) 时要避免默认导入导致测试误连库。

## 19. 是否可以进入 V2.2 P2 AuditLog 持久化

可以。

进入 P2 前建议：

1. 先确定 `HubAuditLog` Prisma 模型字段和索引。
2. 生成独立 migration(数据库迁移)。
3. 将 `PrismaHubRepository.createAuditLog` 从占位错误改为真实写入。
4. 将 `AuditLogService` 接入 `AuditLogRepositoryPort`。
5. 保持 V1.1 Hub API、V2.1 页面和 P1/P2/P3/P5 API 不变。
