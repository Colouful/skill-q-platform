# V2.2 P3.4 Manifest 写事务切换 Prisma Repository 实施报告

## 1. P3.4 目标

本轮只切换 Manifest(清单) 写事务链路，让 Manifest 创建、更新、归档，Manifest Version(清单版本) 创建、发布、废弃，以及 Manifest Asset(清单资产绑定) 绑定、解绑、排序支持 `HUB_REPOSITORY_MODE=memory/prisma` 双模式。

本轮不切换 Agent Profile(智能体画像) 写事务，不做 Review Workflow(审核流) 全局事务化。

## 2. 修改范围

- 补齐 ManifestRepositoryPort(清单仓储端口) 写方法。
- 新增 ManifestVersionRepositoryPort(清单版本仓储端口)。
- 新增 ManifestAssetBindingRepositoryPort(清单资产绑定仓储端口)。
- 扩展 HubTransactionContext(事务上下文)。
- 扩展 MemoryTransactionManager(内存事务管理器) 和 PrismaTransactionManager(Prisma 事务管理器)。
- 补齐 InMemoryHubRepositoryAdapter(内存 Hub 仓储适配器) 的 Manifest 写能力。
- 补齐 PrismaManifestRepository(Prisma 清单仓储) 的 Manifest 写能力。
- 改造 ManifestGovernanceService(清单治理服务)、ManifestVersionService(清单版本服务)、ManifestAssetBindingService(清单资产绑定服务)。
- 改造 Manifest Admin API(清单管理接口) 写路由使用默认事务服务。
- 新增 P3.4 测试和回归测试。

## 4. Manifest 创建切换说明

Manifest 创建现在通过 TransactionManager(事务管理器) 执行：

- slug / name / scope 必填校验保持不变。
- 默认 status=draft。
- slug 重复继续返回 `MANIFEST_SLUG_ALREADY_EXISTS`。
- 隐私字段继续由 `assertSafeManifestPayload` 拦截。
- memory 模式写入 InMemoryHubRepositoryAdapter。
- prisma 模式写入 PrismaManifestRepository。

## 5. Manifest 更新切换说明

Manifest 更新现在通过 TransactionManager 执行：

- 只允许 draft / rejected 更新基础信息。
- published / deprecated / archived 不允许直接更新。
- 不允许修改 slug。
- rejected 更新后回到 draft。
- 违规继续返回 `MANIFEST_UPDATE_NOT_ALLOWED`。

## 6. Manifest 归档切换说明

Manifest 归档现在通过 TransactionManager 执行：

- 写入 `archivedAt`。
- 状态更新为 archived。
- 不删除历史版本。
- 不删除绑定关系。
- archived 后不允许新增版本。

## 7. Manifest Version 创建切换说明

Manifest Version 创建现在通过 TransactionManager 执行：

- Manifest 必须存在。
- archived Manifest 不允许创建版本。
- version 在同一 Manifest 下唯一。
- 默认 status=draft。
- 默认 installPolicy 为 `cursor` + `["claude-code", "codex"]`。
- 初始 checksum 按 V2.1 规则生成。
- version 重复继续返回 `MANIFEST_VERSION_ALREADY_EXISTS`。

## 8. Manifest Asset 绑定事务说明

绑定事务在同一个 `runInTransaction` 内完成：

1. 校验 Manifest 存在且未 archived。
2. 校验 ManifestVersion 存在且为 draft / reviewing。
3. 校验 Asset 存在且未 archived。
4. 校验 AssetVersion 属于 Asset。
5. 校验 AssetVersion 为 published。
6. 校验 AssetVersion immutable=true。
7. 校验 AssetVersion checksum 存在。
8. 校验不重复绑定同一个 AssetVersion。
9. 校验 kind 与 Asset.kind 一致。
10. 创建绑定关系。
11. 重新计算 ManifestVersion checksum。
12. 写入 AuditLog，action 为 `bind`。
13. 任一步失败整体回滚。

## 9. Manifest Asset 解绑事务说明

解绑事务在同一个事务中完成：

- 校验 ManifestVersion 存在。
- 校验 ManifestVersion 为 draft / reviewing。
- 校验 bindingId 属于当前 ManifestVersion。
- 删除绑定关系。
- 重新计算 checksum。
- 写入 AuditLog，action 为 `unbind`。
- 失败整体回滚。

## 10. Manifest Asset 排序事务说明

排序事务在同一个事务中完成：

- 校验 ManifestVersion 存在。
- 校验 ManifestVersion 为 draft / reviewing。
- 校验所有 bindingId 属于当前 ManifestVersion。
- 校验 order 为数字。
- 更新绑定顺序。
- 重新计算 checksum。
- 写入 AuditLog，action 为 `reorder`。
- 失败整体回滚。

## 11. Manifest Version 发布事务说明

发布事务在同一个 `runInTransaction` 内完成：

1. 校验 Manifest 存在。
2. 校验 ManifestVersion 存在。
3. 校验当前状态可发布。
4. 查询绑定关系并按 order 计算 checksum。
5. 校验至少一个 required AssetVersion。
6. 校验所有绑定 AssetVersion 都是 published。
7. 校验所有绑定 AssetVersion immutable=true。
8. 校验所有绑定 AssetVersion checksum 存在。
9. 重新计算 ManifestVersion checksum。
10. 更新 ManifestVersion status=published。
11. 写入 publishedAt / publishedBy。
12. 更新 Manifest latestVersionId。
13. 更新 Manifest status=published。
14. 写入 AuditLog，action 为 `publish`。
15. 任一步失败整体回滚。

## 12. Manifest Version 废弃切换说明

Manifest Version 废弃现在通过 TransactionManager 执行：

- 只能废弃 published 版本。
- 状态更新为 deprecated。
- 不删除绑定关系。
- 不改变 checksum。
- deprecated 后旧 lock 仍可使用。

## 13. AuditLog 一致性说明

以下动作已与业务写入放在同一事务上下文：

- Manifest Version publish
- Manifest Asset bind
- Manifest Asset unbind
- Manifest Asset reorder

AuditLog 写入失败时，业务状态和 checksum 更新会回滚。

## 14. memory 模式行为

`HUB_REPOSITORY_MODE=memory`：

- Manifest 读写都走 InMemoryHubRepositoryAdapter。
- MemoryTransactionManager 使用快照模拟事务。
- 失败时回滚 manifests、manifestVersions、manifestAssets 和 auditLogs。
- 默认测试模式仍保持 memory。

## 15. prisma 模式行为

`HUB_REPOSITORY_MODE=prisma`：

- Manifest 读写走 PrismaHubRepository / PrismaManifestRepository。
- 事务通过 `prisma.$transaction` 执行。
- 缺少 Prisma Client 时返回中文错误，不静默降级 memory。
