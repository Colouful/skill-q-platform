# V2.1 P5 发布流程与审核占位实施报告

## 1. P5 目标

V2.1 P5 目标是在 P1 Asset(资产) 管理 API(应用程序接口)、P2 Manifest(清单) 管理 API(应用程序接口)、P3 Agent Profile(智能体配置) 管理 API(应用程序接口) 和 P4 Hub(资产中心) 页面基础上，补齐最小可用的发布流程与审核占位闭环。

本轮不实现复杂审批系统，不接入组织架构、RBAC(基于角色的访问控制)、钉钉机器人、OpenClaw(开放执行器)、AI 工程资产生成器，也不修改 br-ai-spec(规范工具) 和 br-ai-spec-visual(可视化平台)。

## 2. 修改范围

- 新增审核流服务与错误码。
- 新增审计日志占位服务与只读查询 API(应用程序接口)。
- 新增 Asset Version(资产版本)、Manifest Version(清单版本)、Agent Profile(智能体配置) 的 submit-review(提交审核) 和 reject(驳回) API(应用程序接口)。
- 现有 publish(发布) API(应用程序接口) 改为通过 ReviewWorkflowService(审核流服务) 写入审计占位。
- Hub(资产中心) 页面补充提交审核、审核通过发布、驳回、发布前检查结果、驳回原因展示和审核状态流转提示。
- 补充 P5 单元测试、API(应用程序接口) 集成测试和页面 smoke test(冒烟测试)。

未修改 Prisma schema(Prisma 数据模型定义)，未新增 migration(数据库迁移)，未修改根目录 `package.json`。

## 5. 新增页面能力

- Asset(资产) 详情页：draft/rejected 版本显示“提交审核”，reviewing 版本显示“审核通过发布”和“驳回”，published 版本显示“已发布，不可修改”，rejected 版本显示驳回原因。
- Manifest(清单) 详情页：draft/rejected 版本显示“提交审核”，reviewing 版本显示“审核通过发布”和“驳回”，发布前展示 required asset(必需资产)、checksum(校验和)、状态检查提示，published 后提示不可解绑和排序。
- Agent Profile(智能体配置) 列表和详情页：draft/rejected 显示“提交审核”，reviewing 显示“审核通过发布”和“驳回”，发布前调用 validate API(校验接口)，展示安全策略检查结果。
- 新增审核状态流转组件、发布前检查组件和审计日志占位组件。

## 6. Asset Version 审核流程

```text
draft/rejected -> submit-review -> reviewing
reviewing -> reject -> rejected
reviewing -> publish -> published
published -> deprecate -> deprecated
```

规则：

- 只能 draft/rejected 提交审核。
- 只能 reviewing 驳回。
- 驳回必须填写 reason(原因)。
- 发布前重新计算 checksum(校验和)，published 后 immutable=true(不可变)。
- published 后不允许直接修改 content(正文)。
- archived Asset(已归档资产) 不允许提交审核。
- 每次提交审核、驳回、发布都会写入审计占位记录。

## 7. Manifest Version 审核流程

```text
draft/rejected -> submit-review -> reviewing
reviewing -> reject -> rejected
reviewing -> publish -> published
published -> deprecate -> deprecated
```

规则：

- 只能 draft/rejected 提交审核。
- 只能 reviewing 驳回。
- 发布前至少绑定一个 required asset(必需资产)。
- 发布前绑定的 AssetVersion(资产版本) 必须为 published(已发布)、immutable=true(不可变) 且有 checksum(校验和)。
- published 后不允许修改绑定资产、不允许解绑、不允许调整顺序。
- archived Manifest(已归档清单) 不允许提交审核。
- 每次提交审核、驳回、发布都会写入审计占位记录。

## 8. Agent Profile 审核流程

```text
draft/rejected -> submit-review -> reviewing
reviewing -> reject -> rejected
reviewing -> publish -> published
published -> deprecate -> deprecated
```

规则：

- 只能 draft/rejected 提交审核。
- 只能 reviewing 驳回。
- 发布前必须通过安全策略校验。
- deniedTools(禁用工具) 必须包含 upload-source、deploy、push、merge。
- contextScope.allowSourceCode 必须为 false。
- contextScope.allowAbsolutePath 必须为 false。
- approvalPolicy.beforePush、beforeMerge、highRiskAlwaysManual 必须为 true。
- published 后不允许修改 content(内容)。
- archived Agent Profile(已归档智能体配置) 不允许提交审核。
- 每次提交审核、驳回、发布都会写入审计占位记录。

## 9. 状态流转规则

本轮补齐的核心流转：

```text
draft -> reviewing
reviewing -> published
reviewing -> rejected
rejected -> reviewing
published -> deprecated
published -> archived
deprecated -> archived
```

兼容策略：

- 为保护 P1/P2/P3 已有 API(应用程序接口) 回归，现有 publish(发布) 服务仍兼容 draft 直接发布。
- P5 页面主路径已调整为先 submit-review(提交审核)，再 reviewing(审核中) 发布。
- 该兼容策略仅用于避免破坏既有测试和调用方；后续如果要强制“必须审核后发布”，应在 P6 验收后单独收紧并同步迁移测试。

## 10. 审计日志占位说明

本轮未新增数据库表，未修改 Prisma schema(Prisma 数据模型定义)。

审计占位采用内存服务：

- `AuditLogService.append`
- `AuditLogService.list`
- `GET /api/hub/admin/audit-logs`

记录字段：

- `targetType`
- `targetId`
- `action`
- `operator`
- `reason`
- `note`
- `statusFrom`
- `statusTo`
- `createdAt`

该实现用于 P5 最小闭环验证。生产级持久化 AuditLog(审计日志) 表可在后续阶段单独设计 migration(数据库迁移)。

## 11. 发布前检查规则

- Asset Version(资产版本)：检查 contentSize(内容大小)、checksum(校验和)、状态是否为 reviewing。
- Manifest Version(清单版本)：检查是否绑定 asset(资产)、checksum(校验和)、状态是否为 reviewing；服务端仍执行 required asset(必需资产) 和 published asset(已发布资产) 强校验。
- Agent Profile(智能体配置)：发布前调用 validate API(校验接口)，检查安全策略、checksum(校验和)、状态是否为 reviewing。

服务端发布仍保留 checksum(校验和)、安全策略、已发布不可变等硬校验，页面检查只作为用户确认前提示。
