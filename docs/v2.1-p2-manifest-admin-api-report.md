## 5. Manifest 创建规则

`POST /api/hub/admin/manifests` 支持创建 draft(草稿) Manifest(清单)。

规则：

- `slug` 必填且唯一。
- `name` 必填。
- `scope` 必填，支持 `platform` / `department` / `team` / `project` / `personal`。
- 默认 `status=draft`。
- 创建时不允许直接 published(已发布)。
- 重复 `slug` 返回 `MANIFEST_SLUG_ALREADY_EXISTS`。
- 请求中不允许 `sourceCode`、`rawPrompt`、`rawResponse`、绝对路径。
- 支持写入 `tags`、`techStacks`、`projectKinds`、`recommendedFor`、`ownerOrgId`、`ownerTeamId`。

## 6. Manifest 更新规则

`PATCH /api/hub/admin/manifests/:manifestId` 支持更新 draft(草稿) / rejected(已驳回) Manifest(清单)基础信息。

规则：

- 只允许更新 `name`、`description`、`tags`、`techStacks`、`projectKinds`、`recommendedFor`、`ownerTeamId`。
- 不允许修改 `slug`。
- published(已发布)、deprecated(已废弃)、archived(已归档) Manifest(清单)不允许直接修改基础信息。
- archived(已归档) Manifest(清单)返回 `MANIFEST_ARCHIVED`。
- 其他违规返回 `MANIFEST_UPDATE_NOT_ALLOWED`。

## 7. Manifest Version 创建规则

`POST /api/hub/admin/manifests/:manifestId/versions` 支持创建 draft(草稿) ManifestVersion(清单版本)。

规则：

- Manifest(清单)必须存在。
- 同一 Manifest(清单)下 `version` 必须唯一。
- 新建版本默认 `status=draft`。
- 默认 `installPolicy.defaultExecutor=cursor`。
- 默认 `installPolicy.fallbackExecutors=["claude-code","codex"]`。
- 新建版本生成初始 checksum(校验和)，绑定资产后重新计算。
- archived(已归档) Manifest(清单)不允许新增版本。
- 重复 `version` 返回 `MANIFEST_VERSION_ALREADY_EXISTS`。

## 8. Manifest Asset 绑定规则

`POST /api/hub/admin/manifests/:manifestId/versions/:versionId/assets` 支持绑定 AssetVersion(资产版本)。

规则：

- ManifestVersion(清单版本)必须存在。
- ManifestVersion(清单版本)必须是 draft(草稿) / reviewing(审核中)。
- Asset(资产)必须存在。
- AssetVersion(资产版本)必须存在并属于该 Asset(资产)。
- Asset(资产)和 AssetVersion(资产版本)都必须是 published(已发布)。
- AssetVersion(资产版本)必须 `immutable=true`。
- AssetVersion(资产版本)必须有 checksum(校验和)。
- archived(已归档) Asset(资产)不允许绑定。
- 同一个 ManifestVersion(清单版本)不允许重复绑定同一个 AssetVersion(资产版本)。
- `kind` 必须与 Asset(资产)的 `kind` 一致，否则返回 `MANIFEST_ASSET_BINDING_NOT_ALLOWED`。
- 绑定后重新计算 ManifestVersion(清单版本) checksum(校验和)。

## 9. Manifest Asset 解绑规则

`DELETE /api/hub/admin/manifests/:manifestId/versions/:versionId/assets/:bindingId` 支持解绑 AssetVersion(资产版本)。

规则：

- ManifestVersion(清单版本)必须是 draft(草稿) / reviewing(审核中)。
- published(已发布) ManifestVersion(清单版本)不允许解绑资产。
- `bindingId` 必须属于当前 ManifestVersion(清单版本)。
- 解绑后重新计算 checksum(校验和)。
- 不删除 Asset(资产)和 AssetVersion(资产版本)本身。

## 10. Manifest Asset 排序规则

`PATCH /api/hub/admin/manifests/:manifestId/versions/:versionId/assets/reorder` 支持调整绑定顺序。

规则：

- ManifestVersion(清单版本)必须是 draft(草稿) / reviewing(审核中)。
- 所有 `bindingId` 必须属于当前 ManifestVersion(清单版本)。
- `order` 必须是数字。
- 调整后重新计算 checksum(校验和)。
- published(已发布) ManifestVersion(清单版本)不允许调整顺序。

## 11. Manifest Version 发布规则

`POST /api/hub/admin/manifests/:manifestId/versions/:versionId/publish` 支持发布 draft(草稿) / reviewing(审核中)版本。

规则：

- 只能发布 draft(草稿) / reviewing(审核中)状态版本。
- ManifestVersion(清单版本)至少绑定一个 required(必需) asset(资产)。
- 所有绑定 AssetVersion(资产版本)必须是 published(已发布)。
- 所有绑定 AssetVersion(资产版本)必须 `immutable=true`。
- 所有绑定 AssetVersion(资产版本)必须有 checksum(校验和)。
- 发布时重新生成 ManifestVersion(清单版本) checksum(校验和)。
- 发布后 `status=published`。
- 写入 `publishedAt`。
- 写入 `publishedBy=system`。
- 更新 `Manifest.latestVersionId`。
- 更新 `Manifest.status=published`。
- published(已发布)后不允许修改绑定资产或调整顺序。

## 12. Manifest Version 废弃规则

`POST /api/hub/admin/manifests/:manifestId/versions/:versionId/deprecate` 支持废弃 published(已发布) ManifestVersion(清单版本)。

规则：

- 只能废弃 published(已发布)版本。
- deprecated(已废弃)后旧 lock(锁文件)仍可使用。
- deprecated(已废弃)版本不应被新推荐默认命中。
- 不删除绑定关系。
- 不改变绑定资产 checksum(校验和)。
- 非 published(已发布)版本返回 `MANIFEST_VERSION_DEPRECATE_NOT_ALLOWED`。

## 13. Manifest 归档规则

`POST /api/hub/admin/manifests/:manifestId/archive` 支持归档 Manifest(清单)。

规则：

- archived(已归档)后 Manifest(清单)不允许新增版本。
- archived(已归档)后 Manifest(清单)不允许修改。
- archived(已归档)后不允许新推荐命中。
- 不删除历史版本。
- 不删除绑定关系。
- 写入 `archivedAt`。

## 14. published ManifestVersion 不可变策略

published(已发布) ManifestVersion(清单版本)不可变策略：

- 发布后状态固定为 `published`。
- 发布后不允许绑定新的 AssetVersion(资产版本)。
- 发布后不允许解绑 AssetVersion(资产版本)。
- 发布后不允许调整绑定顺序。
- 如需调整绑定资产，必须创建新的 ManifestVersion(清单版本)。
- 集成测试覆盖 published(已发布)版本不允许解绑和排序。

## 15. checksum 策略

checksum(校验和)策略：

- ManifestVersion(清单版本)创建时生成初始 checksum(校验和)。
- 绑定、解绑、排序 AssetVersion(资产版本)后重新计算 checksum(校验和)。
- 发布 ManifestVersion(清单版本)时重新计算 checksum(校验和)。
- checksum(校验和)输入包含 ManifestVersion(清单版本)基础信息和按 `order` 排序后的资产绑定摘要。
- deprecated(已废弃) ManifestVersion(清单版本)不改变绑定资产 checksum(校验和)。

## 16. Manifest Export 兼容性说明

现有 `GET /api/hub/manifests/:slug/export` 未改变路径和响应结构。

兼容要求保持：

- 响应继续包含 `schemaVersion`。
- 响应继续包含 `manifest.slug`。
- 响应继续包含 `manifest.version`。
- 响应继续包含 `manifest.checksum`。
- 响应继续包含 `installPolicy`。
- 响应继续包含 `assets`。
- 响应继续包含 `agentProfiles`。
- `assets` 继续包含 `kind` / `slug` / `version` / `checksum` / `required` / `loadWhen` / `contentUrl`。
- Export(导出)只导出 published(已发布) ManifestVersion(清单版本)。
- Export(导出)只导出 published(已发布) AssetVersion(资产版本)。
- draft(草稿) AssetVersion(资产版本)不会被 Export(导出)使用。

deprecated(已废弃) AssetVersion(资产版本)策略说明：

- V2.1 P2 新绑定默认禁止 deprecated(已废弃) AssetVersion(资产版本)。
- 已发布旧 ManifestVersion(清单版本)中的旧 lock(锁定)绑定可继续作为历史版本使用。
- 当前 Export(导出)兼容测试仍要求只导出 published(已发布) asset version(资产版本)，不改变 V1.1 消费契约。
