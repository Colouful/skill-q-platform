# V2.2 P3.3 Asset 写事务切换 Prisma Repository 实施报告

## 1. P3.3 目标

本轮目标是只切换 Asset(资产) 写事务链路，让 Asset 创建、更新、归档以及 Asset Version(资产版本) 创建、发布、废弃支持 `HUB_REPOSITORY_MODE=memory` 和 `HUB_REPOSITORY_MODE=prisma` 双模式。

本轮不切换 Manifest(清单) 写事务，不切换 Agent Profile(智能体画像) 写事务，不重构 Review Workflow(审核流) 全局事务。

## 2. 修改范围

- 新增 TransactionManager(事务管理器) 基础设施。
- 补齐 AssetRepositoryPort(资产仓储端口) 写方法。
- 新增 AssetVersionRepositoryPort(资产版本仓储端口)。
- 补齐 InMemoryHubRepositoryAdapter(内存仓储适配器) 的 Asset / Asset Version 写能力。
- 补齐 PrismaHubRepository(Prisma 仓储) 的 Asset / Asset Version 写能力。
- 改造 AssetGovernanceService(资产治理服务) 支持事务化写入。
- 改造 AssetVersionService(资产版本服务) 支持事务化写入和发布审计。
- 改造 Asset Admin API(资产管理接口) 写路由使用默认事务服务。
- 新增 P3.3 写事务测试和回归测试。

## 3. 新增 TransactionManager 列表

- `src/server/hub/transactions/transaction-manager-port.ts`

- `src/server/hub/transactions/transaction-manager-provider.ts`

## 4. 新增 HubTransactionContext 说明

`HubTransactionContext` 当前暴露：

- `assets`: `AssetRepositoryPort`
- `assetVersions`: `AssetVersionRepositoryPort`
- `auditLogs`: `AuditLogRepositoryPort`

Asset Version 发布时，业务状态更新和 AuditLog(审计日志) 写入使用同一个事务上下文。

## 5. 新增 Asset 写 Repository 方法

`AssetRepositoryPort` 新增：

- `createAsset`
- `updateAssetDraft`
- `archiveAsset`
- `markAssetPublished`
- `findAssetBySlug`

这些方法用于支持 Asset 创建、草稿更新、归档和发布后更新 `latestVersionId`。

## 6. 新增 AssetVersionRepositoryPort 说明

新增 `AssetVersionRepositoryPort`，包含：

- `createAssetVersion`
- `findAssetVersionByAssetAndId`
- `findAssetVersionByAssetAndVersion`
- `publishAssetVersion`
- `deprecateAssetVersion`

该端口隔离 Asset Version 写事务，避免业务服务直接依赖 Prisma Client(Prisma 客户端)。

## 7. Asset 创建切换说明

Asset 创建现在通过 TransactionManager 执行：

- memory 模式写入 InMemoryHubRepositoryAdapter。
- prisma 模式写入 PrismaAssetRepository。
- 创建前继续校验 slug / name / kind / scope。
- slug 重复继续返回 `ASSET_SLUG_ALREADY_EXISTS`。
- 敏感字段继续由隐私校验拦截。

## 8. Asset 更新切换说明

Asset 更新现在通过 TransactionManager 执行：

- 只允许 draft / rejected 状态更新基础信息。
- published / deprecated / archived 不允许直接更新。
- 不允许修改 slug。
- 不允许修改 kind。
- 不允许传入 content。
- rejected 更新后回到 draft。

## 9. Asset 归档切换说明

Asset 归档现在通过 TransactionManager 执行：

- 写入 `archivedAt`。
- 状态更新为 archived。
- 不删除历史版本。
- 不删除 content。
- archived 后禁止新增版本。

## 10. Asset Version 创建切换说明

Asset Version 创建现在通过 TransactionManager 执行：

- asset 必须存在。
- archived asset 不允许创建版本。
- 同一 Asset 下 version 唯一。
- content 必填。
- contentFormat 默认 markdown。
- 默认 status=draft。
- 默认 immutable=false。
- 自动计算 checksum。
- 自动计算 contentSize。

## 11. Asset Version 发布事务说明

发布事务在同一个 `runInTransaction` 内完成：

1. 校验 Asset 存在。
2. 校验 AssetVersion 存在。
3. 校验状态为 draft / reviewing。
4. 校验 content 非空。
5. 重新计算 checksum。
6. 更新 AssetVersion status=published。
7. 设置 AssetVersion immutable=true。
8. 设置 publishedAt / publishedBy。
9. 更新 Asset latestVersionId。
10. 更新 Asset status=published。
11. 写入 AuditLog，action 为 `publish`。
12. 任一步失败整体回滚。

## 12. Asset Version 废弃切换说明

Asset Version 废弃现在通过 TransactionManager 执行：

- 只能废弃 published 版本。
- 状态更新为 deprecated。
- 不删除 content。
- 不改变 checksum。
- 旧 lock 仍可继续使用。

## 13. AuditLog 一致性说明

Asset Version 发布时，AuditLog 写入和版本发布在同一事务上下文中完成。

- AuditLog 写入失败时，AssetVersion 发布回滚。
- AssetVersion 发布失败时，AuditLog 不会单独成功。
- 测试覆盖了 AuditLog 写入失败时状态回滚。

## 14. memory 模式行为

`HUB_REPOSITORY_MODE=memory`：

- 读写都走 InMemoryHubRepositoryAdapter。
- MemoryTransactionManager 使用快照模拟事务。
- 事务失败时回滚 assets、assetVersions 和 auditLogs。
- 默认测试模式仍为 memory，保持 V2.1 兼容。

## 15. prisma 模式行为

`HUB_REPOSITORY_MODE=prisma`：

- Asset 写事务走 PrismaHubRepository。
- PrismaTransactionManager 使用 `prisma.$transaction`。
- 缺少 Prisma Client 时返回中文 HubError，不静默降级 memory。
- 本轮只切 Asset 写事务，Manifest / Agent Profile 写事务尚未切换。

- Prisma Repository 的真实数据库集成仍依赖后续开发库 smoke test。
- `npm run lint` 仍存在历史 warning，需要单独治理。
