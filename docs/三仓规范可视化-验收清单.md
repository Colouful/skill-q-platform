# 三仓规范可视化 — 开发完成度与验收清单

> **依据文档**：`三仓规范可视化-文档包`（PRD、集成契约、里程碑、技术实现总览、测试与验收用例等）

## 一、总体结论（是否「都完成了」）

| 维度 | 结论 | 说明 |
|------|------|------|
| **MVP 闭环**（创建 Manifest → Export → CLI 安装 → hub-lock → Visual 展示 → 上报/统计） | **基本达成** | 三仓均有对应实现；部分接口与文档**路径命名**不同（以 `/api/hub/*` 等实际代码为准），需在集成验收中对照映射表。 |
| **P0**（数据模型、Export、CLI install、hub-lock、资产画像） | **基本达成** | 与 `12-里程碑与任务分解`、技术总览 V1 验收项一致。 |
| **P1**（diff/upgrade/安装记录/运行态回流/配置器增强） | **大部分达成** | Hub 有安装上报与分析页；CLI 提供 diff/sync/upgrade/rollback；Visual 有采集与资产相关能力。需按第八节做端到端复验。 |
| **P2**（智能推荐、高级治理、复杂组织权限、自动评分算法等） | **未视为已全部完成** | 文档定位为后续阶段；Hub 上已有部分效果分析/推荐等级类展示，**不等于**文档中「智能推荐/复杂权限」的完整产品形态。 |

**建议**：在签署「全量完成」前，必须跑通**第八节 E2E** 并满足**第七节 文档与实现差异**的对照说明。

## 二、skill-q-platform（Hub）验收

### 2.1 数据与模型

- [ ] 数据库/Prisma 中存在 Manifest/资产相关实体，且可支撑发布与导出（对照 `03-清单数据模型与版本化.md`、`06-数据库设计.md`）

### 2.2 Hub API（注意：实现路径可能与 PRD 示例不同）

- [ ] **Manifest 列表/详情/发布**：有可用 HTTP 入口（如 `api/hub/manifests` 等，以代码为准）
- [ ] **Manifest Export**：供 CLI 拉取完整安装数据（如 `api/hub/manifests/[id]/export`）
- [ ] **安装预览**（若已上线）：`install-preview` 或等价能力
- [ ] **安装上报**：CLI/Visual 上报的安装记录可写入并可查询/汇总（如 `api/hub/install/report`、分析接口）

- [ ] 响应体约定与错误处理与 `04-Hub-API契约.md` / 技术总览 **code/message/data** 风格一致（以实际中间件为准）

### 2.3 管理端与前台页面

- [ ] **Manifest 列表/新建/编辑/详情** 可访问，核心字段与空态/异常态有处理（`07-前端页面与交互设计`）
- [ ] **方案包/运行效果**相关页（如 `/manifests/analytics`）能展示安装与运行类汇总（与 `AI规范清单-技术实现总览` 第 9、12 章目标一致则视为通过）

- [ ] 上传/安全扫描/风险相关能力与 `10-安全扫描与风险分级` 的**实现范围**已确认（全量/阶段性标注清楚）
- [ ] 与 Visual 的回流若涉及鉴权/幂等，有配置说明（对照 `11-可视化运行反馈协议`）

### 2.5 测试

## 五、三仓联调 E2E（必做，对应文档 `08-测试设计与验收用例`）

按顺序执行并**全程中文提示、无未捕获异常**：

1. [ ] 在 Hub **创建/发布** 可用的 Manifest 或方案包（或选用已有 `enterprise-react-standard` 类试点）
2. [ ] 沙箱业务仓执行 `hub install ... --dry-run`，确认**仅预览、不写盘**
3. [ ] 执行正式 `hub install`，确认 **hub-lock.json** 与 **manifest 注册** 已生成
4. [ ] 在业务仓用 Collector/Hook 上报，Visual 中**能看到该项目下的 Manifest/资产**信息
5. [ ] Hub 侧**安装记录或运行效果分析**有对应增量（以当前 API 能力为准）
6. [ ] 重复安装：**幂等**或符合「checksum 一致则跳过」的预期
7. [ ] 故意制造可恢复冲突，验证**非默认覆盖**、备份或人工提示

## 六、文档与实现差异（登记项，避免假阳性验收）

| 文档/示例 | 实现侧常见差异 | 验收时动作 |
|-----------|----------------|------------|
| `GET /api/manifests/{id}/export` | 可能为 `api/hub/manifests/[id]/export` 或结合 scenario/profile | 以 **OpenAPI/Route 树** 为准，更新对客户的《接口对照表》 |
| `GET /api/assets` 全局资产列表 | 可能与 Scenario/技能市场模型并存 | 在集成文档中写清**主数据入口** |
| 导航结构「方案包/治理中心/运行反馈」**完整 IA** | 可能分阶段上线 | 清单中标注「V1 已上 / V2 计划」 |
| 数据库表名 MySQL 示例 | 可能为 PostgreSQL/Prisma 命名 | 不卡表名，**卡字段语义与约束** |
