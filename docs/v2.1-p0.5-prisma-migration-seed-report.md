# V2.1 P0.5 Prisma Migration / Generated Client / Seed 策略报告

## 1. P0.5 目标

V2.1 P0.5 的目标是固化 P0 数据模型增强之后的三类工程策略：

- Prisma migration(数据库迁移)策略。
- Prisma Client(数据库客户端)生成物策略。
- Hub seed(种子数据)策略。

本轮不开发 Asset 管理 API(资产管理接口)、Manifest 管理 API(清单管理接口)、Agent Profile 管理 API(智能体画像管理接口)，不开发页面，不实现复杂审核流，不修改 br-ai-spec(本地 CLI 与协议工具) 或 br-ai-spec-visual(运行态可视化)。

## 2. schema 变更摘要

P0 已在 `prisma/schema.prisma` 对 Hub 数据模型做最小可空字段增强：

- `HubAsset`：补充标签、可见性、最新版本指针、废弃 / 归档时间、创建人与更新人字段。
- `HubAssetVersion`：补充变更说明、创建人、发布人、驳回信息、来源、内容大小、上一版本指针字段。
- `HubManifest`：补充标签、技术栈、项目类型、推荐场景、最新版本指针、废弃 / 归档时间、创建人与更新人字段。
- `HubManifestVersion`：补充变更说明、创建人、发布人、驳回信息、上一版本指针、导出协议版本字段。
- `HubManifestAsset`：补充别名、绑定原因、阶段、添加人、添加时间、策略字段。
- `HubAgentProfile`：补充归属组织 / 团队 / 用户、风险等级、创建人、发布人、废弃 / 归档时间字段。
- `HubInstallRecord`：补充 Manifest(清单)、状态、失败原因、包数量、客户端名称和版本等冗余查询字段。
- `HubRuntimeFeedback`：补充 Manifest(清单)、成功状态、耗时、失败分类、执行器类型、资产 slug 列表、隐私校验标记等冗余查询字段。

所有新增字段均为 nullable(可空)，未删除字段，未重命名字段，未修改现有 Hub API(Hub 接口)响应结构。

## 3. migration 是否已生成

已生成。

生成方式：

- 这样可以避免把历史上已存在于 schema(模型定义)、但未出现在旧 migration(迁移目录)里的 Hub 基础建表误并入本轮 P0.5 migration(数据库迁移)。

## 5. 未直接执行 migrate dev 的原因

项目已有 `prisma/migrations/`，但历史 migration(数据库迁移)中未发现 Hub 基础表相关 SQL，而当前 schema(模型定义)已经包含 Hub 模型。

如果直接执行 `npx prisma migrate dev --name v2_1_hub_governance_fields --schema prisma/schema.prisma`，存在风险：

- 需要连接开发数据库。
- 可能把历史 Hub 基础建表差异和本轮字段增强混入同一个 migration(数据库迁移)。
- 不适合在未确认开发数据库状态时自动执行。

因此本轮采用 schema-to-schema diff(schema 对 schema 差异)方式生成最小 SQL，并将生产 / 开发库实际执行留给后续数据库变更流程。

## 6. 推荐 migration 命令

后续如需在开发数据库中按 Prisma 标准流程生成或验证 migration(数据库迁移)，建议使用：

```bash
npx prisma migrate dev --name v2_1_hub_governance_fields --schema prisma/schema.prisma
```

执行要求：

- 必须连接开发数据库，不能连接生产数据库。
- 不能在生产库直接执行。
- 执行前需要备份数据库。
- 执行后需要运行 `npx prisma validate --schema prisma/schema.prisma`。
- 执行后需要重新生成 Prisma Client(数据库客户端)。
- 执行后需要运行 Hub API(Hub 接口)契约测试和隐私契约测试。

## 8. src/generated/prisma 是否建议纳入提交

本项目 Prisma Client(数据库客户端)生成物是否提交：是。

原因：

- `src/generated/prisma/*` 已经被 Git 版本管理跟踪。
- `.gitignore` 未忽略 `src/generated/prisma`。
- 根目录 `package.json` 中 Prisma generator(生成器)明确输出到 `../src/generated/prisma`。
- 项目存在 `postinstall` 和 `prisma:generate` 脚本，说明本地依赖安装后会尝试保持 Prisma Client(数据库客户端)可用。
- 继续提交生成物可以避免 schema(模型定义)新增字段后 TypeScript(类型系统)或 LSP(语言服务)先报字段不存在。

后续开发要求：

- 修改 `prisma/schema.prisma` 后必须执行 `npx prisma generate --schema prisma/schema.prisma` 或项目等价脚本。
- 生成物变化需要和 schema(模型定义)变化一起评审。
- 不要手工编辑 `src/generated/prisma/*`。
- 不要为了清理 diff(差异)删除 `src/generated/prisma/*`。

## 9. src/generated/prisma/package.json 说明

`src/generated/prisma/package.json` 是 Prisma Client(数据库客户端)生成物内部元信息，不是根目录 `package.json`。

本轮遵守约束：

- 未修改根目录 `package.json`。
- 未新增依赖。
- 未删除 `src/generated/prisma`。

`src/generated/prisma/package.json` 中的 `name` 会随 Prisma Client(数据库客户端)生成内容变化而更新，属于生成物同步的一部分。

## 15. 当前风险点

当前风险点：

- 历史 migration(数据库迁移)中没有 Hub 基础表 SQL，但 schema(模型定义)中已有 Hub 模型；后续数据库环境需要确认 Hub 表是通过哪条流程创建的。
- 本轮 migration(数据库迁移)按 schema-to-schema diff(schema 对 schema 差异)生成，只覆盖 P0 字段增强；如果目标数据库缺少 Hub 基础表，不能直接执行本 migration(数据库迁移)。
- Prisma Client(数据库客户端)生成物 diff(差异)较大，需要代码评审时确认与 schema(模型定义)一致。
- 新增字段全部 nullable(可空)，但生产执行前仍需要评估索引、表大小、锁表风险和回滚策略。
- 复杂审核流、Asset 管理 API(资产管理接口)、Manifest 管理 API(清单管理接口)仍未实现，属于 P1 后续范围。
