# V2.2 P3.6 Review Workflow 全局事务化实施报告

## 1. P3.6 目标

本轮目标是把 P5 阶段的 Review Workflow(审核流) 从历史内存路径升级为统一事务化路径，保证 Asset Version(资产版本)、Manifest Version(清单版本)、Agent Profile(智能体配置) 的 submit-review(提交审核)、reject(驳回)、publish(发布) 读写同源，并保证状态变更与 AuditLog(审计日志) 写入在同一事务边界内完成。

## 2. 修改范围

- 改造 ReviewWorkflowService(审核流服务)，使 submit-review / reject 依赖 TransactionManager(事务管理器) 和 Repository Port(仓储端口)。
- 补齐 AssetVersionRepositoryPort / ManifestVersionRepositoryPort / AgentProfileRepositoryPort 的审核状态写方法。
- 补齐 InMemory Repository(内存仓储) 与 Prisma Repository(Prisma 仓储) 对审核状态写方法的实现。
- 调整 submit-review / reject API route(接口路由)，改为使用默认 ReviewWorkflowService，避免继续绑定历史 defaultHubRepository(默认 Hub 仓储)。
- 增加 ReviewWorkflow(审核流) 事务、双模式、隐私和 API 回归测试。
- 未修改 Prisma schema(Prisma 数据模型)、migration(迁移) 和 package.json(依赖配置)。

## 3. ReviewWorkflowService 改造说明

ReviewWorkflowService 现在支持注入 TransactionManagerPort(事务管理器端口)，默认通过 getHubTransactionManager(获取 Hub 事务管理器) 按 `HUB_REPOSITORY_MODE` 创建 memory(内存) 或 prisma(Prisma) 模式事务。

兼容旧测试和旧调用方式：如果构造函数传入 HubRepository(内存 Hub 仓储)，会自动包装 MemoryTransactionManager(内存事务管理器)，并保留旧 AuditLogService(审计日志服务) 的追加能力。

## 4. submit-review 事务说明

submit-review 现在在同一个 `runInTransaction` 事务中完成：

1. 查询目标资源。
2. 校验目标存在。
3. 校验状态必须是 draft / rejected。
4. 校验 archived 资源不可操作。
5. 通过 Repository Port 更新状态为 reviewing。
6. 写入 AuditLog，action 为 `submit-review`。
7. 任一步失败整体回滚。

## 5. reject 事务说明

reject 现在在同一个 `runInTransaction` 事务中完成：

1. 校验 reason 必填。
2. 查询目标资源。
3. 校验目标存在。
4. 校验状态必须是 reviewing。
5. 通过 Repository Port 更新状态为 rejected。
6. 如模型支持，写入 rejectedAt / rejectedReason。
7. 写入 AuditLog，action 为 `reject`。
8. 任一步失败整体回滚。

## 6. publish 委托说明

publish 主路径由 ReviewWorkflowService 负责先校验当前状态必须为 reviewing，然后委托已完成事务化的领域服务执行：

- asset-version -> AssetVersionService.publish
- manifest-version -> ManifestVersionService.publish
- agent-profile -> AgentProfileGovernanceService.publish

领域发布服务已在 P3.3 / P3.4 / P3.5 中负责 checksum(校验和)、published immutable(已发布不可变)、安全策略和 AuditLog 写入，因此 ReviewWorkflowService 不重复写 publish 审计。

## 7. Asset Version 审核事务说明

Asset Version 支持：

- draft / rejected -> reviewing。
- reviewing -> rejected。
- reviewing -> published 走 AssetVersionService.publish。
- submit-review / reject 不修改 content、checksum、immutable。
- publish 保持 checksum 重新计算、immutable=true、Asset.latestVersionId 更新和 AuditLog 同事务一致。

## 8. Manifest Version 审核事务说明

Manifest Version 支持：

- draft / rejected -> reviewing。
- reviewing -> rejected。
- reviewing -> published 走 ManifestVersionService.publish。
- submit-review / reject 不修改绑定关系和 checksum。
- publish 继续校验 required asset、绑定 AssetVersion 均为 published、immutable=true、checksum 存在，并保持 Manifest.latestVersionId 更新和 AuditLog 同事务一致。

## 9. Agent Profile 审核事务说明

Agent Profile 支持：

- draft / rejected -> reviewing。
- reviewing -> rejected。
- reviewing -> published 走 AgentProfileGovernanceService.publish。
- submit-review / reject 不修改 content、checksum、安全策略。
- publish 继续强制 deniedTools、contextScope、approvalPolicy 安全策略校验，校验失败时状态和 AuditLog 均不写入。

## 10. AuditLog 一致性说明

submit-review / reject 由 ReviewWorkflowService 在同一事务内写 AuditLog。AuditLog 写入失败时，业务状态回滚；业务状态更新失败时，AuditLog 不会单独成功。

publish 继续由领域发布服务写 AuditLog，并保持业务发布和 AuditLog 同事务一致。

## 11. AuditLog 去重说明

ReviewWorkflowService 的 publish 不再额外写入 publish AuditLog，避免同一次审核通过发布产生重复审计记录。新增测试覆盖 Agent Profile publish 只产生一条 `action=publish` 审计记录。

## 12. memory 模式行为

`HUB_REPOSITORY_MODE=memory` 时：

- submit-review / reject / publish 读写都走 InMemoryHubRepositoryAdapter(内存 Hub 仓储适配器)。
- MemoryTransactionManager 使用快照回滚。
- 不需要 Prisma Client(Prisma 客户端)。
- 适用于单元测试和本地快速验证。

## 13. prisma 模式行为

`HUB_REPOSITORY_MODE=prisma` 时：

- submit-review / reject 通过 Prisma Repository 更新状态。
- PrismaTransactionManager 使用 `prisma.$transaction`。
- 业务服务不直接依赖 Prisma Client。
- 本轮用 mock Prisma Client(模拟 Prisma 客户端) 覆盖 submit-review / reject 双模式测试；真实开发库 smoke test(冒烟测试) 留到 P3.7。
